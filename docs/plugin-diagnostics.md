# 内置插件诊断与真实浏览器验收

## 诊断命令

在宿主机执行：

```bash
dshd doctor plugins
dshd doctor plugins --json
```

诊断器只读检查运行中的 DSH Docker 容器，并按状态输出：

| 状态 | 含义 |
| --- | --- |
| OK | 文件/启动参数/浏览器模块/API 检查通过 |
| OFF | 可选功能（如关闭的 Web Search）没有注册到当前 Web 进程 |
| FAIL | 必需功能缺失、加载失败、重复加载风险或运行 API 异常 |

检查内容：

1. 镜像中存在每个内置插件的 `package.json`、`index.js`、`client.js` 和 `cordis.patch.yml`，且包名正确。
2. DSH Web 进程通过官方 CLI `--patch` 参数加载内置插件；参数必须在 Web 应用选项之前。
3. 旧 Web Profile 不应再同时选中相同的内置插件；第三方包不会被检查为故障或被修改。
4. 容器内通过本机地址、现有登录 Token 取得认证 Cookie，验证真实 HTML 注入的 `__DSH_BOOT__` 包含所有启用的内置前端模块。
5. 验证回收站管理的已认证 API 返回可解析的会话列表。

此命令不运行 pnpm，不读写第三方插件设置，不创建用户会话，也不会输出 Token/Cookie。返回码 0 表示通过，非零表示需要查看诊断项目。

**适用条件：** 容器必须已经运行；如果 Web 尚未启动，先使用 `dshd logs` 检查启动失败原因。

## Chromium E2E 发版门禁

`tests/test-web-browser-e2e.cjs` 使用镜像内自带的 Chromium 和 Playwright，在 CI **新建、可销毁的数据卷**上测试：

- Web 登录后原生侧边栏与 Icon Dock 的接管及原始图标入口。
- 展开状态最多 5 列、2 行；超过 9 个显示「更多」并能执行原本的回调。
- 「更多/隐藏」分类和排序在页面刷新后保持。
- 从官方插件入口进入「快捷入口管理」并显示可视化预览及位置选择控件。
- 所有上述验证在真实 Web 进程、官方客户端模块系统及 Chromium 中执行，不再只依赖 React 模拟环境。

测试中的临时快捷入口只存在于独立 CI 浏览器；不对生产用户安装插件、不删除会话。

注意：这是 Web UI 烟雾验收，不是完整的视觉回归快照或跨浏览器兼容矩阵。上游 DSH 的 CSS 或导航结构变化可能导致验收失败，届时应先检查真实兼容性，再决定是否更新测试。

## 失败时操作

诊断不通过时，优先查看哪一项 FAIL：`launcher`、插件包名、`legacy:...`、`client-graph` 或 `api:...`。

不要为修复内置插件而删除 Web Profile、修改 pnpm 锁文件，或关闭第三方供应链验证。内置插件应由 Docker 镜像加载，与用户自行安装的第三方插件彼此独立。
