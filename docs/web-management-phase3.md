# Web 管理迁移 · 第三批：统一管理前端

> 基于第一批的管理任务契约与第二批的 25 项受控运维操作。本批只修改 Web 界面和相关测试，不扩大宿主机执行器的能力与权限。第三批 PR 依赖第二批 PR。

## 页面结构

现有 `dsh-instance-manager` 插件在插件详情页和独立 Overlay 内使用同一个 `Panel`，采用可响应式收缩的管理导航。

| 页面 | 核心功能 | 边界 |
|---|---|---|
| 总览 | 当前容器状态、版本、健康、升级提醒与快捷入口 | 单实例快照，不推测实时未获取状态 |
| 实例 | 当前绑定实例身份、Edition、镜像、状态及管理操作 | **不**提供跨实例切换、新建或任意实例 ID |
| 版本与更新 | 更新检查、自动检查周期、重建、回滚、Edition / Research Pack | 第二批固定枚举，不开放自定义镜像 |
| 网络与服务 | sing-box、订阅、节点、Research Dashboard | 保持第一二批服务端白名单 |
| 配置与诊断 | API Key 配置状态（非明文）、存储模式、Docker 权限提示、环境/插件诊断 | 不开放密钥读取/改写、Shell、Docker Socket |
| 任务记录 | 当前任务详情、最近任务、状态筛选、操作或任务 ID 搜索 | 后台任务未结束不能重复执行；中断任务严禁自动重放 |
| 运行日志 | SSE 追踪、查询、级别筛选、暂停、重新连接 | 宿主机限量、脱敏日志，不执行宿主命令 |

## 交互规范

- 桌面采用紧凑侧栏，窄屏采用可横向滚动的导航栏；原生 Plugin Hub 详情和 Overlay 复用样式。
- 全局状态栏显示绑定实例、运行健康、Edition 与执行器在线情况；在任意非任务页面都能进入最近执行任务。
- 危险的「清理旧容器与镜像」不仅要读确认说明，还必须输入**当前实例名称**，提交前校验；换页面会自动撤销尚未提交的确认。
- 任务详情区展示状态、执行时间、受限日志和已脱敏的错误；通过状态及操作/任务 ID 筛选历史。遇到 `interrupted`，明确提示不得自动重试。
- 全部控制都沿用宿主机能力判断，当前实例后台离线、忙碌时禁用提交；不把浏览器禁用按钮当作授权机制，服务端继续双重验证。
- 导航使用 tablist/tabpanel 语义，支持方向键、Home 和 End；Overlay 沿用 Esc 关闭与焦点约束。
- 状态与内容有明确空状态，减少原来的大卡片和无意义留白。只读操作与危险操作视觉区分，移动端使用紧凑布局。

## 验收与回归

```bash
node --check docker/plugins/dsh-instance-manager/client.js
node --test tests/test-instance-manager-ui.cjs
node --test tests/test-instance-manager.mjs tests/test-management-operations.mjs
python3 tests/test-web-manager.py
```

新增/更新 UI 检查：七页导航、单实例隔离提示、键盘导航、老宿主机缺失能力时禁用按钮、危险清理实例名确认、取消确认、任务筛选与状态持久显示。已有日志 SSE、镜像检查、故障断连恢复测试必须保持通过。

这批仅为**插件内的 Web 管理中心统一改造**，不是 DSH 应用所有管理页面或原生 Plugin Hub 的全局重设计。浏览器实际渲染和真实 Docker 行为仍以 CI/E2E 环境结果为准。完整终端菜单精简留给第四批，不能先删除底层 CLI 命令。
